# 网页意图确认门 · 90% 置信度

这是 Atelier 的核心特色：先确认客户想要的设计，再制作完整作品。
置信度是六轴加权的工作流评分，表示设计意图确认程度，不是统计正确率。

## 六轴与权重

| 轴 | 信号 | 权重 | 确认依据 |
|---|---|---|---|
| A | 页面用途/类型 | 15% | 落地页、官网、作品集、后台等具体用途 |
| B | 目标受众 | 10% | 用户明确给出，或已有产品上下文 |
| C | 风格方向/语调 | 30% | 明确视觉方向、参考设计或选中的预览 |
| D | 视觉锚点/品牌 | 25% | 品牌色、logo、字体、现有设计系统或明确的品牌约束 |
| E | 布局偏好 | 10% | 首屏形态、内容组织，或已确认的现有版式 |
| F | 参考与灵感 | 10% | 链接、截图、现有页面，或明确不使用外部参考 |

每轴取值：明确给出/确认 = 1.0；有依据的强推断 = 0.7；
仅有弱线索 = 0.4；完全未知 = 0。保留每轴的依据。

- 用户对某轴说“你定”或明确确认“不需要”，表示该轴已作出决定，按 1.0 计。
- 已有设计系统、现有页面可作为 C/D/E/F 的依据，不要求再给一个外部链接。
  按实际内容分别判断；不能因为只存在一个文件就把所有轴填满。
- 完全未提及参考是未知；用户明确说“没有参考，不需要”是已确认的选择。
- 同品牌和修改稿复用未变的已确认信号，仅重评本次实际变化的轴。

**总置信度 = Σ(轴权重 × 轴取值)。**

## 门控规则

- **≥90%**：输出设计意图确认单，开始最终设计，不再等待形式批准。
- **<90%**：每轮只问一个最大缺口的问题。缺口 = 权重 × (1 − 轴值)。
  给两三个具体选项，并允许自由回答或委托；不重复问已明确的信息。
- 通常一两轮，最多三轮；仍未达到门槛时，给具体设计方案供用户确认。
  对方确认后更新相应轴并重算；明确委托则走下面的委托路径。
  不能自行把不足的分数补成 90%，也不把三轮已过当作默认同意。
- 明确交付物后直接路由，不额外问“网页还是 PPT”。
- 风格预览属于探索，可以在门未通过时制作；完整成品需通过门或获明确委托。

例如轴值 A/B/C/E = 1.0、D/F = 0.4，置信度为 79%；
仅选中风格不能补齐品牌与参考。确认 D 后，其余不变，得分为 94%。

## 明确委托路径

用户说“直接做 / 你定 / 不用问”时，保留原 skill 的委托豁免：
在确认单写“按用户委托通过”，公开重要设计假设后执行。
不为委托虚构一个数字；已经有依据的轴分数可以保留，但不声称事实已核实。

委托只允许自行决定设计偏好，不能代替必须引用的产品资料、原文件或数据。
缺少必需事实材料时指出具体缺口，不杜撰客户评价、业绩和引用。

## 简短确认单

```text
设计意图已确认（置信度 94%；依据六轴评分）。
交付：企业会议助手落地页，跟随现有 React 项目。
设计：米白 + 深绿、编辑杂志风、左右分栏；保留现有字体。
内容：基于产品说明，无客户评价则不添加评价区。
```

百分数必须用当次轴值计算，不能照抄示例。
委托时第一行改为“设计意图已确认（按用户委托通过）”，并写清重要假设。

按用途选择[风格库](style-taxonomy.md)和[布局库](layout-archetypes.md)，
用户参考与已有系统优先。局部调整不重走全部流程，只检查发生变化的信号。
